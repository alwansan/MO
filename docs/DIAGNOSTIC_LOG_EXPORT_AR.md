# MO P12 — سجل الأحداث الكامل المتاح داخل تطبيق MO وتصدير Download/log.txt
تاريخ: 2026-11-07 | session `MO-20261107-CHAT-P12-LOG-EXPORT-020`

## طلب المالك والتنفيذ
المالك لم يختبر P11 على هاتفه بعد. طلب زرًا ينسخ السجل إلى الحافظة، ويحفظ ملف `log.txt` مباشرة داخل `/storage/emulated/0/Download`، ويحتوي الأحداث مع التوقيت كي يرفع الملف عند مواجهة خلل.

أضفنا نظام التسجيل إلى **التطبيقين المنفصلين**:
- `com.alwansan.mo` — **MO Graphics Probe v0.10.0-alpha.10**: أحداث تشغيل الواجهة، فحوص CPU/GPU/Vulkan، نتائج Shizuku الواردة للتطبيق الرئيسي، محاولات وأخطاء إجراءات GPU Debug المملوكة فقط، وإنشاء نسخة من لوحات المعلومات عند التصدير.
- `com.alwansan.mo.glesprobe` — **MO Layer Test v0.6.0**: جلسات التشغيل، أحداث الأنشطة، فحوص EGL/GLES/NDK، قراءات المختبر والاختيارات الوهمية، اختبارات وتيرة الرسم `stride 1/2/4` مع نتائج عدد callbacks/draws في نوافذ ~1 ثانية، أخطاء Java غير الملتقطة وأحداث انخفاض الذاكرة.

**حدود السجل:** لا يوفر سجل `logcat` شاملًا للجهاز، ولا يستطيع الاطلاع على أحداث العمليات المغلقة أو تحميل سجلات Monster Hunter Outlanders أو تحريك FPS اللعبة. ليس تسجيل فيديو للشاشة. لا تُسجّل كلمات المرور أو الحسابات عمدًا؛ لكن stacktrace قد يتضمن مسارات أو رسائل أخطاء، لذلك راجع الملف قبل رفعه. تطبيقات Android معزولة، لذا لكل تطبيق ملفه الخاص، ولا يستطيع أحدهما جمع السجلات الداخلية للآخر.

## صيغة الأحداث
كل سطر يبدأ بتاريخ محلي دقيق يتضمن إزاحة المنطقة الزمنية، مثل `2026-11-07T05:00:00.123+0300`، ثم `elapsed_ms` لوقت التشغيل الأحادي، PID، رقم thread، نوع الحدث، والتفاصيل. تتضمن السجلات أوقات إنشاء الأنشطة وإغلاقها، بدء الجلسات، القياسات، تبديل وضع المحاكاة، الفشل، Memory trim، وUNCAUGHT_CRASH إن أمكن استدعاء handler قبل إنهاء العملية.

تُسجَّل الأحداث داخل ملفات خاصة بالتطبيق أثناء عمله. بعد إعادة تشغيل التطبيق يمكن تصدير الأحداث السابقة **طالما لم تُمسح بياناته ولم يُحذف**. للحماية من استهلاك التخزين: تحتفظ النسخة الحالية بأحدث **3 ملفات × 3 MiB**؛ الأحداث الأقدم قد تُحذف تلقائيًا بعد تجاوز هذا الحد. هذا هو **السجل الكامل المتاح ضمن سياسة الاحتفاظ**، وليس سجلًا لا محدودًا منذ تاريخ تثبيت Android. السجل السابق قبل إدخال الميزة لا يمكن استرجاعه.

## طريقة الاستخدام
1. ثبّت أحدث APK التجريبي المناسب من **GitHub Releases** بعد نجاح CI. لا تُثبّت تطبيق MO الرئيسي فقط من أجل تجربة المختبر إذا لم تكن تحتاج تشخيص Shizuku؛ تطبيق Layer Test قادر على تسجيل تجاربه مستقلًا. الاختبار لا يحتاج root أو Shizuku.
2. افتح التطبيق وشغّل التجربة (إذا كنت تختبر P11 فجرّب الرسم كل 1/2/4 تحديثات). الأحداث تُحفظ تلقائيًا أثناء الجلسة.
3. اضغط **«إخراج السجل: نسخه + حفظ Download/log.txt»** من إحدى صفحات الاختبار أو الصفحة الرئيسية في تطبيق MO الرئيسي.
4. التطبيق يلتقط نسخة مرتبة من الأحداث ثم يحاول إنشاء `Download/log.txt` بواسطة `MediaStore.Downloads` على Android 10+، مع `RELATIVE_PATH=Download/` و`IS_PENDING` أثناء الإنشاء؛ دون MANAGE_EXTERNAL_STORAGE أو READ/WRITE_EXTERNAL_STORAGE أو root.
5. عند التكرار يحاول تحديث **URI محفوظًا ومملوكًا للتطبيق**؛ لا يكتب فوق ملف مملوك لتطبيق آخر. إن وُجد اسم `log.txt` سابق أو تعارض مزوّد ملفات، قد يختار Android اسمًا مثل `log (1).txt`؛ يعرض التطبيق **اسم الملف النهائي الذي أكده MediaStore** أسفل الزر. لا تفترض اسمًا لم تؤكده الواجهة.
6. يُنسخ السجل الكامل للحافظة إن كان ≤180000 حرف. إن تجاوز حد الحافظة العملي، تُنسخ أحدث 180000 حرف مع تحذير صريح، بينما يبقى **السجل الكامل المتاح** في ملف Download. فشل الحافظة لا يعني فشل الحفظ والعكس صحيح؛ تظهر رسالة لكل منهما.
7. افتح مدير ملفات الهاتف → Download، وارفع `log.txt` أو الاسم الذي عرضه التطبيق. إذا استخدمت MO الرئيسي وMO Layer Test معًا، صدّر **كل تطبيق على حدة**، واحفظ الملفين بأسماء مميزة قبل رفعهما كي لا تختلط الأدلة.

## شروط السلامة
- أيقونات التسجيل والتصدير لا تستدعي Shizuku، ولا تغيّر `Settings.Global` ولا تعيد تفعيل GLES Debug.
- لا تعيد تثبيت تطبيق أو تزيل لعبة من أجل هذا الاختبار؛ بيانات سجل التطبيق الداخلية **تُفقد عند إزالة التطبيق**.
- آخر معلومة من المستخدم: استعاد إعدادات GPU Debug ثم حذف تطبيقًا (الاسم غير محدد)؛ **إفادة مستخدم** لا تتضمن قراءة مستقلة للمفاتيح الأربعة. لا نعد تراجع GPU Debug مثبتًا آليًا.
- التصدير إلى Download لا يتطلب صلاحية إدارة كل الملفات في Android 15: مرجع [Android Developers — media files and MediaStore Downloads](https://developer.android.com/training/data-storage/shared/media).
- سجلات خطأ Shizuku الناتجة في عمليات خدمة مستقلة تُضم إلى السجل الرئيسي **عند وصول استجابتها للواجهة**؛ ليس لدينا صلاحية قراءة سجلات أخرى أو شيفرتها المحمية.
- يمكن مشاركة السجل يدويًا مع المساعد، لكنه لا يُرفع تلقائيًا لأي خادم.
- **لا يشير "log كامل" إلى Logcat نظام كامل**؛ لا تدعِ أنه يتجاوز عزل Android.

## مصادقة قبل اعتبار الميزة جاهزة
- اختبارات JUnit للتنسيق والوقت والفصل بين الأسطر.
- بناء `:app:testDebugUnitTest` و`:probe:testDebugUnitTest` و`:app:assembleDebug` و`:probe:assembleDebug` في GitHub Actions.
- رفع ملفَي APK منفصلين مباشرَين في Release، مع SHA-256.
- **اختبار الهاتف المطلوب:** فتح كل تطبيق، إنتاج بعض الأحداث، الضغط على الزر، التحقق من النتيجة ووجود `log.txt` أو الاسم المعلن ضمن Download ورفع نسخة للتحقق. يظل اختبار MediaStore على POCO غير مثبت حتى إرسالك الملف.
