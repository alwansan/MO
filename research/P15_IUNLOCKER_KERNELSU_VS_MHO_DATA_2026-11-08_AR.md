## Confirmed mechanism: root/Zygisk module, **not** an Android/data text file
- Official public i-Taylo/iUnlockerGL README explicitly lists **Magisk v26.4+ or KernelSU root**; KernelSU also requires ZygiskNext; module is installed and device rebooted. `module.prop` identifies `v1.1.5-r4`.
- Repo includes `zygisk` native .so binaries and a separate manager APK. It advertises spoof of OpenGL renderer/vendor/version/extensions, Vulkan model/driver/memory/limits, Build/device identity and CPU/memory. Mechanism is app-process graphics/runtime hooking enabled by rooted Zygisk environment. **It is not enough to enter a string into Android/data; no-root Shizuku UID2000 cannot make stock nondebuggable Outlanders load a similar external module.**
- iUnlocker official license prohibits reverse engineering, modification, creation of derivatives and reuse of code. We reviewed public README/license only; **do not borrow/patch its restricted binaries or decompile it**. Source: https://github.com/i-Taylo/iUnlockerGL and https://github.com/i-Taylo/iUnlockerGL/releases/tag/v1.1.5-r4.
- Another open project with different license `yadavnikhil03/GameUnlocker` documents root/Zygisk Java Build and native property hooks; such examples reinforce runtime scope vs data-file-only but still **require root**. https://github.com/yadavnikhil03/GameUnlocker.
- An app-starter launcher alone can't perform this injection, and user-space virtualization sandbox can't change already installed stock game's process unless the game is hosted differently. Game isolation & official rootless GLES eligibility documented at https://developer.android.com/ndk/guides/rootless-debug-gles.

- Previous private archive `com.tencent.mhadv.zip` was validated/read-only in prior session: **87 ZIP entries = 53 files+34 dirs; ~241 MB uncompressed; nine `MHMobile*.log` Unreal encoded lines, 17 HotRes files, one `GLSL_ES3_1_ANDROID...` shader PrecacheBinaries 55.6MB; no `*.ini`, `*.xml`, `*.properties`, `*.db`, `*.sqlite`**. `LaunchMountPaks.txt` references additional `/data/user/0/com.tencent.mhadv/files/PufferRes` private resource files absent from upload.
- Unreal Engine in general uses `DeviceProfiles` and `GameUserSettings` config classes and may read project-specific Android INI files; official reference https://dev.epicgames.com/documentation/unreal-engine/configuration-files-in-unreal-engine ; https://dev.epicgames.com/documentation/unreal-engine/customizing-device-profiles-and-scalability-in-unreal-engine-projects-for-android. **Those are engine generalities, not evidence Outlanders scans arbitrary user-created .ini from its external Android/data at runtime.** This commercial game can cook its config into PAK, use private app storage, online entitlement and/or verify hot-update assets.
- PUBG/BGMI has documented `UserCustom.ini` in its own `UE4Game/ShadowTrackerExtra/.../Saved/Config/Android/` in third-party guides, but that path and config keys are **PUBG-specific**. Creating PUBG-style config in MHO `files/UnrealGame/MHMobile` cannot be assumed to work. The existence of PUBG fixes historically does not transfer them automatically to MHO.
- Patching hotfix `.pak`, `.utoc`, `.ucas`, or GL shader cache is **higher risk**: changes executable/render resource data, may be rejected/re-downloaded, break game start, or trigger anti-tamper; no demonstrated GPU whitelist or usable writable target file exists in supplied archive. **Do not generate a speculative file for owner to paste.** User asked for a working trial but the necessary mechanism has not been established; test without altering account/game first.

Do not cross into private `/data/user/0` or export tokens.
- Real device identity changes via graphics API require runtime/driver interception, user-authorized app/container context, or official system ANGLE driver (conditional only for GLES), **not** a cache config rename.

## أداة فحص مسار حفظ الإعدادات — **بدون تعديل أي ملف لعبة**
Created `tools/compare_android_data_snapshots.py` as a read-only Python stdlib utility (suitable for Termux), to compare **two user-exported ZIP archives** of `Android/data/com.tencent.mhadv` before and after **changing a setting using the normal in-game UI**. It compares archive-entry paths, byte length and ZIP CRC, without extracting any resource, running binaries, creating settings, or writing to the game's directories. It emits only metadata; original private contents stay on phone. Untrusted duplicate/traversal ZIP paths are rejected.
```bash
pkg install python
python compare_android_data_snapshots.py BEFORE.zip AFTER.zip --output differences.txt
# To include noisy logs/cache changes:
python compare_android_data_snapshots.py BEFORE.zip AFTER.zip --all
```
If the only differences are in logs/cache, the result **does not prove** that the graphics whitelist is stored in Android/data; the game could use private /data/user/0, cooked PAK or server profiles. A changed .ini is still not proof it is trusted/loaded until an authorized game setting A/B confirms. Script source is published on GitHub but was **not runtime-tested locally this turn** because the code execution/container environment was unavailable; no CI/test claim is made.
